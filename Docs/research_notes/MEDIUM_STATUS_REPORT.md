## 1. 现象：三个可断言的数字

`verify_medium_wave.py`（96²、`εr = 2.25`、PEC、EB 移出域外、无界面）：

| 判据 | 期望 | 实测 | 结果 |
|---|---|---|---|
| 能量漂移 | ≤ 1% | **1.663e+05**（`max/E0 = 166293`） | **FAIL** |
| 相速度 | `c/√εr = 1.9986e8` | `1.4454e8`（−27.7%） | **FAIL** |
| 两探针振幅比 | 0.5 – 2.0 | `B/A = 0.000`（A=0.1735，B=0.0000） | **FAIL** |

三条放在一起看，比"探针读数 0.098"清楚得多：

- **不是衰减，是能量增长 16 万倍**。此前用单探针观察，把"局部场为零"误读成"整体衰减"；
- **相速度慢 27.7%**，对应"有效 εr ≈ 4.3"，而输入是 2.25——缩放不是"少乘一次 1/εr"这种整数倍错误；
- **z=0.3 处完全没有信号**，但能量在涨——增长发生在局部（边界附近），不是行波。

## 4. 未解根因：两条待验证的假设

### 假设 A：E 在一步内被更新两次

`WarpXEvolve.cpp:649` 是二选一：

```cpp
if (m_em_solver_medium == Vacuum)            EvolveE(dt);
else if (m_em_solver_medium == Macroscopic)  MacroscopicEvolveE(dt);
```

但 `EvolveE` 还被其它路径调用（`WarpXEvolve.cpp:1245/1297/1307/1346/1395/1414`，AMR/回退路径）。
若介质算例误走其中一条，`E` 会被"真空完整更新 + 介质 0.444 更新"叠加 → 每步多注入 `dE`：

- 这能解释**能量线性增长**（每步注入固定量）；
- 也能解释**波速偏快**（真空分量把相速往 `c` 拉），但实测是**慢** 27.7%，方向相反 —— **不完全吻合**。

### 假设 B：`dE` 与 `E` 的缩放关系被间接破坏

若 `dE` 的有效缩放不是 `0.444` 而是 `0.523`（`0.723²`，由 `v_sim/v_th = 0.723` 反推），
则"慢 27.7%"与"能量涨"可以同时来自一个**非线性的反馈**：`E` 变大 → `B` 更新用 `E` 的环量 →
`B` 变大 → 下一步 `dE` 更大。这不是简单的缩放错误。

**判别方法（各一次运行）**：

1. 在 `WarpX::EvolveE` 与 `WarpX::MacroscopicEvolveE` 各加一个 `static` 调用计数，跑 5 步，
   看 `E` 每步被更新几次 —— 直接判定假设 A；
2. 在 ECT 内核里用 `ReduceMax` 统计 `Σ|dE| / Σ|E|` 的逐步值 —— 若它随步数单调增，
   是正反馈（假设 B）；若恒定，则是一次性缩放错误。

## 7. 结论

1. **介质当前不可用**，且失败发生在最简配置（均匀 εr、无界面、无粒子），不是"界面精度"问题；
2. 三条对照（ECT 真空 OK、Yee 介质 OK、ECT+介质 FAIL）把问题夹在 `has_macro` 分支内部；
3. 六条假设已排除，剩两条（双更新、非线性反馈）各有一次运行可判；
4. 审计的 P2/P3/P4/P6/P8/P9 仍未修，其中 **P6（无界面回归）是这些问题长期不可见的制度性原因**；
5. PEC cut-cell 的工作可以继续，与介质隔离。

> 一句话：**介质的问题不是"精度不够"，而是"均匀介质下能量涨 16 万倍"——
> 这是一个功能性缺陷，不是标定问题；在它被修好之前，`algo.em_solver_medium = macroscopic`
> 只应作为待验证的实验通道使用。**
